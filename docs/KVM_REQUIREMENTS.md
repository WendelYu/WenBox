# WenBox 键鼠流转（KVM）需求文档

- 版本：v0.4（M3 文本同步与恢复边界更新）
- 日期：2026-10-30
- 适用仓库：wenbox（Tauri 1.5 + Rust，桌面端）
- 状态：v1.4.9 整合文本同步、消息身份修复与部分恢复监测；验收边界见 KVM_M3_INTEGRATION.md


当前进度（2026-10-30）：M2.6 已合入 main 并发布 v1.4.7，包含自定义修饰键、按需文件、速度与安装引导。M3.0 正在验证文本剪贴板、按对端保存映射、紧急停止及 Mac 独立核心健康监测。既有用户已确认双机鼠标、键盘和管理员/UAC 操作可用；故障注入、时延、睡眠恢复、多显示器等指标仍需分别验收，不能用正常操作成功替代。

---

当前实现约定：默认 Mac 为主控、Windows 接收输入；同一套主控键鼠能跨屏并返回。交换物理键鼠来源需要解除配对后更换角色，尚不支持双方实体键鼠同时接管。发现范围为局域网 WenBox 设备（包含房间成员），房间 PIN 不授予键鼠控制权限。当前锁定输入组件要求 macOS 14+；双机配对后，在两端 WenBox 已运行且流转启用时自动连接，不包含启动 Mac 登录项或 Windows 登录前控制。

## 1. 一句话

让 WenBox 在同一个房间内，把一台机器的鼠标和键盘"借"给另一台机器用：光标从屏幕边缘移出去就进到对端，键盘跟着光标走；Mac ↔ Windows 双机双向、四方向可配置，不装第二个软件、不改配置文件。

## 2. 背景

WenBox 目前解决的是"现场实施时机器之间传文件"的问题：自带房间、成员发现、PIN 准入、消息与快传。现场的真实工作流里，传完文件紧接着就要操作对方机器——装环境、改配置、跑脚本。现在这一步只能靠人站起来换键盘，或者另装一套 KVM 软件。

目标是把这一步也收进 WenBox：一台机器解决"传文件 + 控机器"。

## 3. 目标与非目标

### 3.1 目标

1. 在 WenBox 内启用后，鼠标可从屏幕边缘跨到对端，键盘跟随光标所在机器。
2. 首版支持一台 Mac ↔ 一台 Windows 双向控制；不要求三机拓扑或 Windows ↔ Windows。
3. 复用房间与成员发现，首次两端确认配对后记住设备，日常自动连接，不手抄指纹、不改配置文件。
4. 纯局域网，不依赖互联网、账号或第三方服务。
5. 在支持的系统与故障范围内可靠释放输入；输入来源恢复本机操作，目标端释放远程按键和按钮。
6. Windows 已登录时，即使未接实体键鼠，也必须能操作管理员终端、安装程序和 UAC 安全桌面。

### 3.2 非目标

1. 不做远程桌面 / 画面传输（对端有自己的显示器）。
2. 不做跨公网、NAT 穿透、中继服务器。
3. 不让 Android 端、浏览器访客作为被控端（拿不到全局输入注入能力）。
4. 不做自动部署、不替换现场机器上已有的程序（与现有 README 的边界一致）。
5. 一期不做剪贴板同步和多显示器精细布局；文本剪贴板为 P1 必做，图片与文件剪贴板后续评估。
6. 一期不支持启动前界面、Windows 登录/锁屏解锁、Ctrl+Alt+Delete 安全注意序列；重启后需通过其他方式登录。
7. 不解决未安装、未配对设备的无输入首次部署；允许提前借用键鼠或已有管理通道完成初始化。

## 4. 用户与场景

### 4.1 角色

- **主控方 / 输入来源**：捕获实体键鼠输入并发送的机器；控制 Windows 时，Mac 仍是输入来源。
- **被控方**：接收并注入输入。
- 同一台机器在不同时刻可以是任意一方。

### 4.2 场景 A：现场实施（主要场景）

一台 Mac（开发/打包）+ 一台 Windows（现场机，可无实体键鼠），同处一个房间、同一个局域网。用户坐在 Mac 前，需要频繁切到 Windows 上操作。

### 4.3 场景 B：网线直连

现场没有可用 Wi-Fi、也没有空闲网口，用 USB 网卡 + 网线把两台机器直连。此时没有 DHCP，依赖链路本地地址或手动地址；WenBox 现有的子网探测需要在这种情况下仍能发现对端。

### 4.4 场景 C：日常双机

Mac 与 Windows 并排放在桌上，希望一套键鼠控两台，减少桌面设备。

### 4.5 场景约束

1. 每台机器都有独立显示器，不需要搬画面。
2. 用户可提前完成一次管理员安装及两端配对；日常 WenBox 主界面无需整体以管理员身份运行。Windows 特权组件的具体形式由 M0 验证确定。
3. 机器可能休眠、可能拔插网线、可能临时断网。
4. macOS 与 Windows 的键盘修饰键语义不同（⌘/Ctrl、Option/Alt）。
5. 主要自用，现有程序已开源；具体许可证及第三方代码兼容性仍需在引入依赖前核实。
6. Windows 必须已登录且显示器可见；无实体键鼠是首版支持场景，不可用“接一个鼠标”作为验收替代。

## 5. 术语

| 术语 | 含义 |
| --- | --- |
| 流转 / KVM | 跨机共享鼠标键盘的能力 |
| 当前目标 | 当前接收输入的机器；与房间房主不是同一概念 |
| 边缘切换 | 光标移出本机屏幕边界即切到对应方向的对端 |
| 紧急释放 | 一键把所有输入收回本机 |
| 房间 | WenBox 现有的成员集合与准入单位 |

| 优先级 | 内容 | 说明 |
| --- | --- | --- |
| P0 | 双机配对、布局、键鼠、Windows 管理员窗口与 UAC、无实体键鼠、释放、重连、诊断 | 首版必做 |

## 7. 功能需求

### FR-01 设备发现与成员展示（P0）

复用房间成员表，在"流转"页展示同房间内可被控/可主控的机器：平台、在线状态、是否已开启流转、当前延迟。

**验收**

- 两台机器加入同一房间后 5 秒内互相出现在列表中。
- 拔掉网线后 10 秒内标记为离线，列表不消失（保留占位）。
- 成员上线后自动恢复可用状态，不需要手动刷新页面。

### FR-02 开启流转与授权（P0）

本机"允许被控"开关默认关闭。开启前检查系统权限，缺失时给出可操作的引导。房间成员身份不等于控制授权。首次配对两端核对绑定设备密钥的短验证码并确认，持久保存设备身份与授权；已配对且允许被控时日常自动连接。

**验收**

- 默认关闭；关闭状态下任何对端都无法向本机注入输入。
- 未授予系统权限时开关置灰并给出说明，不出现"打开了但没反应"。
- 授权状态在成员卡片上可见（已授权 / 待授权 / 被拒绝）。
- 重启与地址变化不要求重复配对；密钥变化必须重新确认，不得静默替换。
- 可单独撤销设备授权；关闭被控立即停止注入。首次默认关闭，之后保留用户明确选择。

### FR-03 屏幕布局（P0）

首版选择一个已配对的对端，指定相对方位（左/右/上/下），默认右侧。双端同步互为反向的进入/返回边缘；单屏为首版验收基线。

**验收**

- 修改方位后立即生效，无需重启应用或重连。
- 方位冲突（两个对端都在右侧）时有明确提示，不允许保存。
- 布局至少在本机持久化，重启后保留。

### FR-04 鼠标流转（P0）

光标移动到屏幕边缘并继续外推时，切换到该方向的对端；切换后对端光标出现在对应的进入边缘，位置按比例映射。本机光标隐藏（可配置）。

**验收**

- 四个方向都能切出、切回。
- 同网线直连下，从移动到切出的 p95 延迟 ≤ 30ms（主观"跟手"）。
- 快速来回切换 20 次不丢失光标、不出现双光标。
- 对端未开启流转时，边缘不切换，光标停在本机边界。

### FR-05 键盘流转（P0）

键盘事件始终发往当前目标。切换目标的瞬间，释放旧目标上由本会话注入的所有按键与鼠标按钮，避免粘键与拖拽卡住；首版按住按键/按钮时不跨边缘，先松开再切换。

**验收**

- 按住 Shift 或鼠标按钮时不跨边缘，松开后可切换；异常断线后不残留远程按下状态。
- 连续切换 100 次，不出现卡键、连击、丢键。
- 中文输入法在各自机器上独立工作；切换目标不自动切换输入法（见 10.3）。

### FR-06 收回本机与紧急释放（P0）

提供全局热键（默认 `Ctrl+Alt+Esc`，可改）与 UI 按钮，一键把键鼠收回本机并断开当前会话。对端失联或网络中断时，输入来源在 2 秒内收回；目标端独立超时释放远程输入。进程崩溃与挂死须通过故障注入验证，不能仅依赖同线程清理。

**验收**

- 热键由输入来源本地处理，在支持的普通应用场景及目标端 UAC 显示期间可用，不依赖目标端或网络响应。
- 从触发到本机可正常操作 ≤ 100ms（主动释放）、≤ 2s（被动失联）。
- 正常连接下主动释放使目标立即停收；网络不可达时目标按超时释放。旧会话迟到输入不得重新注入。
- 进入锁屏、注销等不支持场景时暂停控制并释放输入，明确提示需先完成本地登录。

### FR-07 连接状态与诊断（P0）

显示当前目标、加密状态、RTT、丢包率、本次会话时长；提供"复制诊断信息"。

**验收**

- RTT 每秒刷新，数值与系统 ping 同量级。
- 诊断信息包含：版本、平台、权限状态、端口、最近 50 条连接事件（不含键入内容）。
- 断线原因可读（对端离线 / 权限被撤销 / 端口占用 / 指纹不匹配）。

### FR-08 系统权限引导（P0）

macOS 按实际输入后端检查辅助功能、输入监控及系统要求的本地网络权限。Windows 首次安装须授予特权组件所需权限；普通模式不可冒充已支持 UAC。

**验收**

- 未授权时给出分步图文指引，并提供"打开系统设置"按钮。
- 授权后提供"重新检测"，无需重启应用即可生效（若系统限制必须重启，明确写出）。
- 权限被系统撤销后，下一次连接尝试给出明确错误，而不是静默失败。

### FR-09 断线重连（P0）

网络抖动、休眠唤醒、对端重启后自动重连，采用指数退避，上限 30 秒；网络恢复、唤醒和服务可达事件触发立即重试，期间保持 UI 状态可见。恢复时间从地址就绪且对端服务可达开始计时。

**验收**

- 拔插网线 3 次，每次 15 秒内自动恢复。
- Mac 睡眠 10 分钟唤醒后，15 秒内恢复可用（不要求重启 WenBox）。
- 对端重启并通过其他方式完成登录后，组件自动恢复并连接，无需重新配对；不承诺登录前控制。
- 自动重连恢复为可用状态，不自动抢走本机输入；用户再次越过边缘才开始控制。

### FR-10 双机控制归属（P0）

同一控制会话只有一个输入来源和一个当前目标。双向是两台机器都具备发起控制的能力，不要求同时互相控制；无实体键鼠的 Windows 可以仅作为目标。

**验收**

- Mac → Windows → Mac 往返成功；Windows 有实体键鼠时验证反向控制。
- 双端同时请求控制时明确拒绝冲突请求，不产生输入回路。
- 目标存在实体键鼠时，本地显式接管优先并结束远程会话。

### FR-11 文本剪贴板同步（P1，后续必做）

首版可不实现；后续必须提供已授权双机之间的文本双向同步，可单独关闭，有大小上限与超限提示。图片与文件剪贴板暂不承诺。

**验收**

- 复制 1MB UTF-8 文本，在已连接且网络正常时 1 秒内出现在对端剪贴板。
- 支持中文、多行命令，防止双端同步回环；不自动执行复制的命令。
- 关闭后停止传输并取消监听/轮询；撤销授权或断开会话后停止同步。
- 超限内容给出提示，不静默丢弃；日志不记录剪贴板内容。

### FR-12 修饰键映射（P0 基础版 / P1 完善）

默认把 Mac 的 ⌘ 映射为 Windows 的 Ctrl、Option 映射为 Alt；首版提供"直通"模式；自定义映射列入 P1。

**验收**

- Mac 上按 ⌘C，Windows 端触发 Ctrl+C。
- 可切换为直通，切换后立即生效。
- 映射规则按对端保存，不同对端可用不同规则。

### FR-13 多显示器（P1）

P1 每个物理屏幕参与边缘判断；P0 只承诺每端单屏，多屏精细行为不作为首版验收项。

**验收**

- Mac 双屏时，从最右侧屏的右缘切出能进入右侧对端。
- 显示器数量或分辨率变化后，边缘判定在 2 秒内更新。

### FR-14 隔离与降级（P0）

流转功能异常不得影响房间、文件传输、消息等既有能力。

**验收**

- 注入可恢复 panic、终止输入辅助进程和模拟服务失联后，文件传输与房间功能仍正常；恢复或重新启用前保持输入已释放。
- 流转未启用时，不监听 KVM 数据端口。

### FR-15 Windows 提权与无实体键鼠（P0，发布阻断项）

在已登录 Windows、无实体鼠标键盘的情况下，通过 Mac 操作管理员终端、安装程序及 UAC 安全桌面的确认或凭据输入，完成后正常返回普通桌面。允许提前用其他输入手段完成首次管理员安装与配对。

**验收**

- 保持 UAC 及安全桌面开启，分别验证同意/拒绝和系统策略允许的管理员凭据输入；不存储或记录凭据。
- 拔掉目标机实体键鼠后，普通桌面与 UAC 中光标可见、移动点击及键盘输入可用；无法通过即不满足首版。
- 普通桌面 → 管理员终端 → 安装器 → UAC → 普通桌面连续循环 20 次，无失控或卡键。
- UAC 显示时断网或终止输入代理，Mac 在 2 秒内恢复操作；恢复网络后可重新进入目标操作。
- 默认不提升整个文件/HTTP 服务；特权组件只接受已认证且获授权的输入会话，验证本地 IPC 权限、会话失效和撤权。
- 锁屏/登录前控制不在一期范围；重启后的自动连接从已登录且组件就绪起验收。

| NFR-10 | 可观测 | 关键路径有日志分级，默认 info，可切 debug 而不刷屏 |

## 9. 交互需求

### 9.1 信息架构

- 新增视图 `view-kvm`（"流转"），入口放在房间页工具条与侧栏，与"快传""工具"同级。
- 页面结构：顶部状态条（已连接 · 加密 · 12ms）→ 本机卡片（开关 + 权限状态）→ 成员卡片列表（平台、状态、方位选择、延迟）→ 布局画布（本机居中，对端四向）。
- 断开、关闭被控、紧急释放立即执行，不二次确认；配对和授予控制权限需明确确认。

### 9.2 状态机

`未启用 → 待授权 → 连接中 → 已连接 → 已暂停/错误 → 未启用`

每个状态都必须有对应的 UI 表现与一句人话解释；不允许出现"转圈但没有原因"。

### 9.3 文案

- 用现场用户能懂的话：不出现 scancode、DTLS、CGEventTap 这类词。
- 失败必须给下一步动作（去授权 / 换方向 / 检查网线 / 看诊断）。

## 10. 平台限制（必须向用户明示，不得隐藏）

### 10.1 macOS

- 根据锁定后端和系统版本实测所需辅助功能/输入监控权限，不以固定双权限假设替代检测。
- macOS 15+ 还需要"本地网络"权限。
- 签名或应用身份变化可能影响 TCC 授权；使用稳定身份并验证升级后的权限保留。
- 部分系统版本上 Wi-Fi 的 awdl 会造成光标抖动，需在文档中给出说明。

### 10.2 Windows

- 普通进程受 UIPI 限制；管理员窗口与 UAC 安全桌面是不同验证项，仅“以管理员身份运行”不作为满足 UAC 的证明。
- 优先验证后台服务配合交互会话/桌面输入代理的方案。服务存在本身不保证能控制安全桌面；不得关闭 UAC、安全桌面或降低系统策略以通过验收。
- 无实体鼠标可能导致上游光标不可见，这是必须解决并验证的首版问题，不能仅写成已知限制。
- 首次安装及配对可预先完成；登录前控制不属于一期，已登录桌面与 UAC 控制属于一期。

### 10.3 键盘与输入法

- 切屏不自动切换输入法，中英文状态各自维护。
- 部分 AltGr 组合键在跨平台时行为不一致，属已知限制。

### 10.4 其他

- Android 端与浏览器访客只作为"可见但不可被控"的成员展示。
- 保留一个用户可见的 WenBox 应用及安装入口；允许安装包内包含后台服务/辅助进程，不要求用户另装另一款软件。

## 11. 技术约束与实现路线

### 11.1 现状

- 桌面端 Tauri 1.5 + Rust 2021；UI 为共享 WebView 页面（`app/src/main/assets/web/`）。
- 已有：嵌入式 HTTP 服务（9527）、UDP 发现（9528）、房间/成员/PIN/令牌、文件与消息通道。
- 缺少：输入捕获与注入、低延迟数据面、会话加密与密钥协商。

### 11.2 复用策略（M0 核心路径接受后的 M1 决策）

选择独立进程/服务适配 Deskflow 1.27.0。首轮复用已安装、已配对的后端，通过其固定本地 IPC 控制生命周期；不复制上游源码进 WenBox，不要求特权代码进入 Tauri 主进程。Windows 继续采用已测试的后台服务/system 输入进程路径。

统一安装包、服务权限及升级、设备认证和后端许可分发在后续实现中处理。lan-mouse 暂不采用：v0.11.0 Windows 注入失败存在无上限重试，且缺少本轮需要的安全桌面服务路径。不得默认混合两个候选的 GPL 源码。

### 11.3 控制面与数据面

- 当前 M1 控制面：仅本机可信 Tauri 主窗口可调用的固定原生命令，不新增 HTTP 输入控制接口。
- 后续 M2：房间成员用于发现候选设备；首次确认认证设备身份，不能通过普通 HTTP 房间令牌直接授予控制权限。
- 输入数据面：由 Deskflow 提供 TLS/TCP，当前默认 24800；不新增原 lan-mouse 设想的 UDP 9529，也不占用现有 9527/9528。
- M1 沿用已有后端证书信任，不自动写指纹；密钥变化或撤权的完整 WenBox 管理仍待后续实现。

### 11.4 执行模型

原生命令通过 Tauri spawn_blocking 执行后端检测和有超时的本地 IPC，不阻塞 UI 线程。Mac 管理独立输入子进程，Windows 仅恢复后台服务已保存的标准配置。退出清理由 WenBox 启动的后端；不接管未由本次 WenBox 启动的已有会话。不能将后台服务 ACK 等同于对端连接成功。

### 11.5 当前代码落点

```

src-tauri/src/kvm/config.rs          # 只读标准后端配置与安全检查

app/src/main/assets/web/index.html   # view-kvm 入口和内容

```

## 13. 里程碑与工作量

1. **M0（前置门槛）**：真实 Mac + Windows 双机验证普通桌面、管理员终端、安装器、UAC 安全桌面及无实体鼠标光标；保持系统安全设置；验证后台组件权限、首次安装和故障恢复。输出版本、环境、录屏、失败项与选型结论。
2. **M1**：确定后端与许可兼容性，集成捕获/注入、Windows 特权组件及安装/卸载生命周期。
3. **M2**：接入认证配对、设备身份持久化、双机布局、自动连接与 UI。
4. **M3**：完成紧急释放、重连、诊断、权限引导、并发文件传输与稳定性验收。
5. **M4（P1 必做）**：文本剪贴板双向同步与关闭/超限/回环测试。本轮 M3.0 提前实现其代码和自动回归，真实双机系统剪贴板时延仍待验收。

原 12–19 人日估算基于“不支持 Windows UAC”的旧范围，现已失效。M0 通过后再估算；三机范围虽已移除，但不能抵消尚未验证的特权桌面集成成本。M0 未通过时不得以仅普通桌面可用宣称满足首版。

性能目标仍为待验证指标：明确输入捕获到目标注入的计时方法、时钟同步误差与样本量；屏幕可见延迟另测，RTT 不代替操作延迟。安装包增量分别按 Windows 与 macOS universal 成品测量。

## 15. 已确认决策与待验证事项

### 15.1 用户已确认（2026-10-27）

1. 首版一台 Mac + 一台 Windows，不需要三台。
2. Windows 可能没有实体键鼠；管理员终端、安装程序、UAC 弹窗必须可操作。
3. 可以提前借用键鼠或已有管理通道完成一次管理员安装及首次配对。
4. 两端确认后记住设备，日常自动连接。
5. 主要自己使用，程序已开源；不据此推定已同意更换具体许可证。
6. 文本剪贴板不要求首版，但后续必须实现。
7. 暂不要求无人登录时控制登录界面；一期覆盖已登录桌面及 UAC。安装重启后需先通过其他方式登录。

### 15.2 实现前验证

- 实际 Windows 版本、UAC 策略与硬件上的安全桌面输入、无鼠标光标、特权组件部署。
- 后端版本、许可证兼容性、签名要求及安装包体积；不修改系统安全策略作为兼容手段。
- macOS 各目标版本的权限与线程约束，Windows/Mac 双端故障释放。
