# USB 网卡加网线直连

适用于带 Rust 后台的 **Tauri 原生客户端**，目标组合为 Windows 10 ↔ Windows 10、Windows 10 ↔ macOS、macOS ↔ macOS。两端均需使用包含本次改动的版本。Electron 包目前不内置网络后台，不能单独完成此流程。

## 现场连接

1. 如果两端都没有空闲网口，各接一个 USB-A 或 USB-C 转 RJ45 的 USB 网卡，再用普通网线连接。若一端有空闲网口，只需给另一端加 USB 网卡。
2. 使用已确认支持目标 Win10/macOS 版本的网卡；离线现场要选系统自带驱动可识别的型号，或事先安装好厂商驱动。
3. 这条新增连接保持系统默认的自动获取 IPv4。无需路由器、互联网、网关或 DNS，也无需启用网络共享。原有工控网口可继续连接设备。
4. 两端打开 WenBox，或先打开后插线。无 DHCP 服务时，等待系统完成地址自分配，直到两端新增网卡都有 `169.254.x.x` 地址。地址产生的等待时间由系统决定，不能保证插线后立刻连接。
5. 默认免密房间通过 UDP 自动发现。两端选出同一个房主，另一端自动加入；状态栏显示“网线直连 · 已自动连接”，即可发送文字、图片和文件。

Windows 10 可能把无网关的直连识别为“未识别的网络 / 公用网络”。首次运行时允许 WenBox 在这条连接上收发；若管理员配置防火墙，需允许 WenBox 的 TCP 9527 和 UDP 9528 入站。无需打开 Windows 文件共享或关闭整个防火墙。macOS 首次请求本地网络访问时选择允许；也需允许应用接收入站连接。企业策略禁止新增网卡或本地网络通信时，应用无法绕过策略。

## 自动连接的边界

- 自动连接只用于两端的默认免密房间，并且实际收到的对端地址是 `169.254.x.x`；现有办公 LAN 上的普通房间不会触发自动加入。
- 两端都处于空闲默认房间时，按唯一房间 ID 排序选出一个房主，避免双方同时互相加入。
- 本机已有共享文件、聊天记录或在线成员时，会保留本机房间；另一端可加入这个已有会话。不会自动离开手动创建的房间或密码房。
- 手动创建、选择其他房间、解散或退出后，本次页面会话暂停自动连接，避免马上被重新拉入。重启客户端可重新启用默认流程。
- 同时发现多个符合条件的直连房间时不替用户选设备，可解散本机默认房间后在发现大厅手动选择；普通交换机网络也可能产生链路本地地址，它并不证明物理上只有一台对端。
- 拔线后，访客端连续轮询失败会返回发现状态；重新插线并获得地址后继续尝试，房主保留已有会话。
- 手动配置在相同私有子网的地址仍可发现房间，但不触发此处的默认房间自动配对。旧客户端仍可手动加入。

## 排查

- 网卡不出现或没有链路：检查网卡驱动、USB 数据口、网线和指示灯。
- 网卡已连接但仍未分配地址：等待自动配置；检查是否曾设置静态 IP、关闭自动配置，或被企业策略限制。
- 两端已有 `169.254.x.x` 却找不到对方：检查防火墙、本地网络权限以及 UDP 9528 是否被其他 WenBox 进程占用；每台电脑只运行一个网络后台。
- 已发现但无法加入：检查 TCP 9527 入站；也可用“输入地址加入”填写对端的 `http://169.254.x.x:9527`。

## 实现与验证

后台统一枚举 IPv4 地址，包含 APIPA；按 RFC 3927 对链路本地地址使用 `/16` 广播地址。探测、房间广播和单播回复选择对应的本机网卡；组播显式指定出口，并每秒更新接收组成员，支持启动后插入网卡或系统重新分配地址。后台每 2.5 秒主动探测和广播，界面每 2.5 秒尝试默认房间配对。自动加入携带期望的房间 ID，避免发现后对端重建房间造成误入。

macOS 应用包含本地网络权限说明，并为链路本地、回环和 RFC 1918 私有地址配置 HTTP 传输例外，覆盖较新 macOS 的 ATS 限制。没有全局关闭 ATS。参考 [Apple 的本地网络传输配置](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking)。

浏览器回归使用模拟 Tauri 接口验证双端选主、先启动后插线、拔线重连、手动退出和连接期间已有会话的保护，不替代真实 USB 网卡、Windows 防火墙或 macOS 权限验收。Windows 原生测试沿用 Windows 构建工作流；macOS 工作流新增原生测试及 Intel/Apple Silicon 通用应用构建。工作流只有提交后才会运行。

现场验收至少覆盖三个平台组合：先插线后启动、先启动后插线、拔插重连、同时连接办公网络、互发消息、双向传输文件，以及防火墙拒绝后重新授权。不应在没有这些实机结果时宣称已完成跨平台现场验证。
